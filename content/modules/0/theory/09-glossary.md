**Как пользоваться словарём.** Здесь собраны сокращения и понятия модуля. В главах каждое сокращение расшифровано при первом упоминании, а здесь их можно найти все сразу.

## Сокращения

| Сокращение | Расшифровка | Глава |
|---|---|---|
| API | Application Programming Interface, программный интерфейс | 1 |
| ТЗ | техническое задание | 1 |
| SQL | Structured Query Language, язык структурированных запросов | 1 |
| BPMN | Business Process Model and Notation, нотация моделирования бизнес-процессов | 1 |
| UML | Unified Modeling Language, унифицированный язык моделирования | 1 |
| ЖЦ ПО | жизненный цикл программного обеспечения | 2 |
| ISO | International Organization for Standardization, Международная организация по стандартизации | 2 |
| IEC | International Electrotechnical Commission, Международная электротехническая комиссия | 2 |
| ER | Entity-Relationship, «сущность — связь» | 4 |
| CI/CD | Continuous Integration и Continuous Delivery, непрерывная интеграция и доставка | 6 |
| ПМИ | программа и методика испытаний | 7 |

## Понятия

| Термин | Значение | Глава |
|---|---|---|
| Аналитик | роль в проекте: собирает, анализирует и документирует требования и передаёт их команде | 1 |
| Системный аналитик | аналитик, который описывает интеграции, спецификации API и требования к системе | 1 |
| Жизненный цикл ПО | период от решения о создании ПО до его изъятия из эксплуатации | 2 |
| Этап курса | одна из шести групп работ проекта: потребность, требования, проектирование, реализация, сдача, поддержка | 2 |
| Бизнес-цель | измеримый результат, ради которого создают систему | 3 |
| Заинтересованные лица | все, на кого проект влияет или кто влияет на него | 3 |
| Класс пользователей | группа пользователей с общими задачами и правами | 3 |
| Образ и границы проекта | документ с целями, критериями успеха и объёмом первой версии | 3 |
| Требование пользователя | задача, которую пользователь решает с помощью системы | 4 |
| Функциональное требование | что должна делать система | 4 |
| Нефункциональное требование | какой должна быть система: качество, ограничения, интерфейсы | 4 |
| Критерий приёмки | условие, по которому проверяют, что требование выполнено | 4 |
| Трассируемость | связь между целью, требованием и проверкой | 4 |
| Архитектура | из каких частей состоит система и как они взаимодействуют | 5 |
| Интеграция | обмен данными между системами | 5 |
| Тест-кейс | описание одной проверки: шаги и ожидаемый результат | 6 |
| Граничный случай | значение на границе допустимого, например «ровно за 2 часа» | 6 |
| Приёмка | проверка заказчиком, что система соответствует договорённостям | 7 |
| План миграции | порядок переноса данных из старой системы в новую с проверкой и откатом | 7 |
| Сопровождение | изменение ПО и документации после запуска | 7 |
