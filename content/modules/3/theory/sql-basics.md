## 1. Таблицы и ключи

Реляционная база хранит данные в таблицах (отношениях). Строка таблицы — кортеж, столбец — атрибут. Каждую строку нужно уметь однозначно отличить от других, для этого служат ключи (Коннолли, Бегг, с. 124–125).

- Потенциальный ключ — минимальный набор атрибутов, который однозначно определяет строку.
- Первичный ключ — потенциальный ключ, выбранный для идентификации строк. Он есть у каждой таблицы.
- Внешний ключ — атрибут, который ссылается на ключ другой таблицы и связывает таблицы между собой.

Например, `students.id` — первичный ключ, а `enrollments.student_id` — внешний ключ, ссылающийся на `students`. Уникальность в текущих данных ещё не доказывает, что столбец — ключ: это определяется смыслом данных в реальном мире (с. 125).

## 2. Целостность данных

Два основных правила (с. 129–130):

- Целостность сущностей: ни одна часть первичного ключа не может быть NULL.
- Ссылочная целостность: значение внешнего ключа либо совпадает со значением ключа в связанной таблице, либо равно NULL. Нельзя записать студента на курс, которого нет в таблице курсов.

## 3. NULL

NULL означает, что значение неизвестно или неприменимо. Это не ноль и не пустая строка, а отсутствие значения (с. 128–129). Поэтому для проверки используют `IS NULL` и `IS NOT NULL`, а не сравнение `= NULL` (с. 179).

```sql
SELECT name FROM students WHERE city IS NULL;
```

## 4. Оператор SELECT

Минимальный запрос состоит из SELECT и FROM. Остальные части необязательны, но их порядок менять нельзя (с. 170–171):

```sql
SELECT name, city
FROM students
WHERE city = 'Москва'
ORDER BY name;
```

СУБД обрабатывает части запроса в таком порядке: FROM, WHERE, GROUP BY, HAVING, SELECT, ORDER BY. Поэтому WHERE фильтрует строки до группировки. Результат запроса сам является таблицей. Без ORDER BY порядок строк не гарантирован (с. 179).
