> Статус: черновик для рецензии. Источники: «Шаблоны интеграции корпоративных приложений» и RFC 8259 (JSON). В книге нет описания REST и JSON, поэтому по JSON ссылки идут на RFC 8259 (по номерам разделов).

## 1. Сообщение: заголовок и тело

Чтобы передать данные между приложениями, их нужно упаковать в сообщение: наименьшую единицу данных, которую передают по каналу (Шаблоны интеграции, «Сообщение», с. 98). Сообщение состоит из двух частей:

1. **Заголовок** описывает передаваемые данные для системы доставки: адрес отправителя, адрес получателя и т. п.
2. **Тело** содержит сами данные; система доставки, как правило, его не разбирает.

Та же идея лежит в других местах сети: кадры Ethernet, пакеты TCP/IP, письма электронной почты, HTTP-запросы (в них тоже есть заголовки и тело). Для разработчика интеграции важен смысл сообщения. Для удалённого вызова процедуры применяют **сообщение с командой** (с. 169), для передачи данных — **сообщение с данными документа** (с. 171).

## 2. Форматы данных

Приложения должны одинаково понимать данные друг друга. Поэтому при интеграции выбирают общий формат: раньше это был простой текст, в современных решениях книга называет XML («Передача файла», с. 80). Если у отправителя и получателя разные форматы, формат преобразуют по дороге (шаблон «Транслятор сообщений», с. 115).

Два распространённых текстовых формата в API:

- **XML** — разметка тегами; в нём передаются, например, сообщения SOAP.
- **JSON** — компактный текстовый формат, который сегодня чаще всего встречается в REST API.

## 3. JSON

JSON — текстовый формат для записи структурированных данных (RFC 8259, §1). Значение в JSON — это (§3):

- **объект** — пары «имя: значение» в фигурных скобках (§4);
- **массив** — упорядоченный список значений в квадратных скобках; значения в массиве могут быть разных типов (§5);
- **число** — десятичное, с необязательными знаком, дробной частью и степенью; запись вроде `Infinity` или `NaN` недопустима (§6);
- **строка** — текст в двойных кавычках (§7);
- литералы `true`, `false` и `null`, обязательно строчными буквами.

Пример тела запроса для записи студента на курс:

```json
{
  "student_id": 1,
  "course_id": 2
}
```

Что важно знать аналитику:

- **Имена в объекте должны быть уникальными.** RFC рекомендует это; если имена повторяются, разные программы ведут себя по-разному: одни берут последнее значение, другие сообщают об ошибке (§4).
- **Кодировка.** Если JSON передают между системами, не входящими в одну закрытую среду, он должен быть в UTF-8 (§8.1).
- **Тип содержимого** для JSON — `application/json` (регистрация в §11). Он указывается в заголовке `Content-Type` (см. тему «HTTP и REST»).
- **Неверный JSON** (например, пропущена кавычка или запятая) не разберётся программой; поэтому в Postman тело запроса проверяют на корректность.

## 4. SOAP

SOAP — это протокол обмена сообщениями в формате XML. В книге рассматривается версия 1.1 (Шаблоны интеграции, «Сообщение», с. 98).

Сообщение SOAP — XML-документ с корневым элементом **Envelope** («конверт»). Внутри конверта:

- **Header** — необязательный заголовок;
- **Body** — обязательное тело с данными и вызываемой операцией.

Пример запроса «получить студента» (составлен для курса):

```xml
<soap:Envelope xmlns:soap="http://schemas.xmlsoap.org/soap/envelope/">
  <soap:Body>
    <m:GetStudent xmlns:m="https://school.example/students">
      <m:id>1</m:id>
    </m:GetStudent>
  </soap:Body>
</soap:Envelope>
```

Книга замечает, что SOAP-сообщения обычно передают по HTTP, но их можно передать и через систему обмена сообщениями. Тогда сообщение SOAP оказывается внутри сообщения системы доставки: сообщения могут вкладываться друг в друга (с. 98).

## 5. SOAP и REST: что сравнивать

Разные подходы удобно сравнивать по тому, **что находится в запросе**:

| | SOAP | REST API (темы «HTTP и REST») |
|---|---|---|
| Формат сообщения | XML-конверт | чаще JSON |
| Что вызывается | операция в теле сообщения (`GetStudent`) | метод HTTP и адрес ресурса (`GET /students/1`) |
| Транспорт | чаще HTTP, но может быть и очередь сообщений | HTTP |

В обоих случаях приложение вызывает операцию другого приложения по сети, то есть это пример удалённого вызова процедуры в терминах книги (с. 85). Сравнение в таблице составлено для курса; в книге REST не описывается.

## Глоссарий

- **Сообщение:** наименьшая единица передаваемых данных с заголовком и телом.
- **Формат данных:** договорённость о том, как представлены данные (XML, JSON).
- **Envelope:** «конверт» SOAP-сообщения; внутри Header и Body.
- **Media type:** тип содержимого, например `application/json`.
