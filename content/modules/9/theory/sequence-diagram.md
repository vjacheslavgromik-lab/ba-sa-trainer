> Статус: черновик для рецензии. Источник — п. 2.5.2 книги Вендрова. Он описывает базовую нотацию. Синхронные и асинхронные сообщения, полосы активации и условные ветви в нём не рассматриваются, поэтому в этой теме их нет.

## 1. Диаграммы взаимодействия

Диаграммы взаимодействия показывают, как группа объектов взаимодействует в рамках варианта использования или операции класса (Вендров, п. 2.5.2). Обычно диаграмма охватывает один поток событий варианта использования. На ней видны объекты и сообщения, которыми они обмениваются.

**Сообщение** — способ, которым объект-отправитель просит объект-получатель выполнить одну из его операций. Вендров выделяет три вида:

- **информационное:** сообщает получателю информацию для обновления его состояния;
- **запрос:** просит выдать информацию об объекте-получателе;
- **императивное:** просит выполнить действие.

Бывает два вида диаграмм взаимодействия: **диаграммы последовательности** и **кооперативные диаграммы**.

## 2. Диаграмма последовательности

Диаграмма последовательности показывает **временную последовательность событий** в рамках варианта использования (п. 2.5.2). Как её читать:

- В верхней части стоят **действующие лица** и **объекты**, нужные системе для выполнения варианта использования.
- Объект рисуется прямоугольником на вершине пунктирной вертикальной линии. Эта линия называется **линией жизни** и показывает отрезок жизни объекта в процессе взаимодействия.
- **Сообщение** — стрелка между линиями жизни двух объектов (или действующего лица и объекта).
- Сообщения идут **сверху вниз** в том порядке, в котором происходят. Каждое сообщение подписывают хотя бы именем; можно добавить аргументы и управляющую информацию.
- **Самоделегирование** — сообщение, которое объект посылает самому себе; стрелка начинается и заканчивается на одной линии жизни.

Вендров иллюстрирует это примером «Снять деньги со счёта»: клиент вставляет карту, вводит PIN-код и сумму, система проверяет средства и выдаёт деньги. На диаграмме для основного потока сообщения пронумерованы по порядку.

## 3. Как найти объекты

Один из способов искать объекты — выписать **существительные из описания потока событий** (п. 2.5.2). Но на диаграмме бывают объекты, которых в тексте нет:

- **формы** для ввода или просмотра данных, чтобы действующее лицо могло вводить информацию в систему или видеть её;
- **управляющие объекты**, которые управляют последовательностью событий в варианте использования.

## 4. Кооперативная диаграмма

Второй вид диаграммы взаимодействия — кооперативная. Она показывает тот же поток событий, но акцентирует **связи между объектами**, а не время; порядок сообщений указан **номерами** (п. 2.5.2). По диаграмме последовательности легче понять порядок событий, по кооперативной — связи между объектами, поэтому для сценария часто создают обе.

## 5. Пример на API школы

Сценарий «Записать студента на курс»: администратор школы записывает студента на курс через приложение, которое вызывает API школы.

**Участники (сверху диаграммы, слева направо):**

1. Администратор (действующее лицо)
2. Приложение (клиент API)
3. API школы
4. База данных

**Сообщения по порядку (сверху вниз):**

1. Администратор → Приложение: выбрать студента и курс.
2. Приложение → API школы: `POST /enrollments` с телом `{"student_id": 1, "course_id": 2}`.
3. API школы → База данных: проверить, что студент и курс существуют.
4. API школы → База данных: сохранить запись.
5. API школы → Приложение: `201 Created`.
6. Приложение → Администратор: показать «Студент записан».

Если студента или курса нет, на шаге 5 вместо 201 приходит код ошибки (например, 404 или 400): это отдельный поток событий, и для него рисуют собственную диаграмму. Такие ветвления на одной диаграмме источник Вендрова не рассматривает.

**Как проверить диаграмму:** все участники из потока событий присутствуют, у каждого сообщения есть имя, порядок сообщений совпадает с порядком шагов сценария, отдельно показан ответ API.

## Глоссарий

- **Диаграмма последовательности:** диаграмма, где сообщения упорядочены по времени сверху вниз.
- **Линия жизни:** пунктирная вертикальная линия объекта.
- **Сообщение:** стрелка между участниками; вызов операции получателя.
- **Самоделегирование:** сообщение объекта самому себе.
- **Кооперативная диаграмма:** диаграмма, где акцент на связях объектов, порядок задан номерами.
