**Цель главы.** Вы поймёте, какую роль играют HTML (HyperText Markup Language), CSS (Cascading Style Sheets) и JavaScript в интерфейсе, чтобы разговаривать с разработчиками на одном языке и формулировать требования, которые они смогут реализовать.

## Три слоя веб-интерфейса

Веб-интерфейс строится из трёх технологий, у каждой своя роль (MDN):

- **HTML** (HyperText Markup Language, язык гипертекстовой разметки) задаёт **структуру и содержание** страницы и смысл содержимого в машиночитаемом виде. Это важно для доступности, поиска и встроенных возможностей браузера.
- **CSS** (Cascading Style Sheets, каскадные таблицы стилей) задаёт **оформление и раскладку**: шрифты, цвета, размеры, отступы, колонки, анимации. Работает по правилам: селектор выбирает элементы, а блок объявлений задаёт пары «свойство — значение». Браузер сначала строит дерево страницы, а затем применяет стили; у браузера есть и стили по умолчанию.
- **JavaScript** — язык программирования, который добавляет **динамику и поведение**: обновление содержимого, обработку событий, мультимедиа, анимации. Он работает в браузере и может менять HTML и CSS через программный интерфейс страницы. Код разных вкладок изолирован.

Проще: HTML — «скелет», CSS — «одежда», JavaScript — «движение».

## Что из этого следует аналитику

- **Структура** (HTML): какие блоки и элементы есть на странице, как называются разделы и заголовки, какая у них иерархия. Это связано с картой сайта и информационной архитектурой.
- **Оформление** (CSS): цвета, шрифты, отступы чаще задают дизайн и дизайн-система; аналитик фиксирует требования к ним только там, где это нужно бизнесу (фирменный стиль, доступность).
- **Поведение** (JavaScript): проверка полей, подсказки, динамическое обновление списка окон без перезагрузки. Это и есть та часть интерфейса, к которой пишут функциональные требования.
- **Доступность**: структура страницы и смысл элементов важны для людей, использующих вспомогательные технологии; требования к доступности записывают явно.

## Разговор с разработчиком

Полезно уметь задавать вопросы, зная три слоя:

- «Где проверяем телефон: в браузере (JavaScript) или на сервере?» — вопрос о том, на каком слое лежит правило;
- «Что показываем, если скрипт не загрузился?» — вопрос об устойчивости;
- «Какие браузеры и устройства поддерживаем?» — вопрос о требованиях к совместимости.

## Figma и разработка

Макет и прототип в Figma не заменяют HTML, CSS и JavaScript: это проект интерфейса. Разработчик берёт из него структуру, размеры, цвета и поведение и реализует их кодом. Поэтому аналитик следит, чтобы требования к элементам и поведению совпадали с макетом и были понятны разработчику.

## Пример для сети клиник «Вита»: форма записи

- **Структура (HTML):** форма с полями «Специальность», «Врач», «Дата и время», «Телефон» и кнопкой «Записаться».
- **Оформление (CSS):** поля одной ширины, ошибки красным цветом, крупные кнопки для удобного нажатия на смартфоне.
- **Поведение (JavaScript):** при выборе специальности список врачей обновляется без перезагрузки страницы; при вводе неверного телефона показывается сообщение.
- **Требования аналитика:** какие поля обязательны, какие значения допустимы, что показывать при ошибке, на каких устройствах и в каких браузерах форма должна работать.

## Итоги

- HTML задаёт структуру и смысл, CSS — оформление, JavaScript — поведение.
- Требования к поведению пишут для слоя JavaScript и сервера, к структуре — для HTML, к оформлению — через дизайн и дизайн-систему.
- Макет и прототип — проект интерфейса; код делает разработчик.
- Знание трёх слоёв помогает задавать разработчикам точные вопросы.
